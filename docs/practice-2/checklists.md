## Дымовое тестирование

Цель — за 10–15 минут проверить пригодность стенда для детального тестирования. Условия: запустить Compose из текущего репозитория, дождаться готовности зависимостей, использовать только синтетические данные. Проверки выполняются до денежных кейсов; неуспешная готовность ядра блокирует их выполнение.

- [ ] **SM-01.** `docker compose up -d` завершился успешно, `docker compose ps` показывает все 11 сервисов, PostgreSQL и RabbitMQ работающими; health-check успешны там, где настроены, циклических рестартов нет. Основание: [README](../../README.md), [ТЗ-01](../../tz/01-devops.md).
- [ ] **SM-02.** PostgreSQL принимает соединения, миграции CMS и Authorization закончены, есть таблицы карт, резервов, usage и outbox. Требования: C-14, A-08.
- [ ] **SM-03.** Gateway `http://localhost:8080/health` →200, JSON содержит состояние сервисов. Основание: [ТЗ-02 §1](../../tz/02-gateway.md).
- [ ] **SM-04.** Authorization `http://localhost:8083/health` →200, `status=ok`, `service=authorization`, CMS доступен. Требование: A-01.
- [ ] **SM-05.** Card Management `http://localhost:8081/health` →200, `status=ok`, `service=card-management`, есть `cardsInDatabase`. Основание: [ТЗ-05 §1](../../tz/05-card-management.md).

- [ ] **SM-08.** `POST /api/cards/generate` через Gateway, count20, bins400000–400004 →201, generated20, PAN валидны по Luhn; `GET /api/cards` возвращает карты. Требования: C-05, C-08, C-10, C-11.

- [ ] **SM-10.** `GET http://localhost:8096/api/bin/400000` возвращает issuerId ISS001; `GET http://localhost:8097/api/notifications` →200. Основание: [scripts/smoke-test.sh](../../scripts/smoke-test.sh), A-10, C-15.

Его зелёный результат проверяет запуск и базовую связь, но не заменяет SM-09: скрипт допускает DECLINED случайной карты и использует фиксированную дату запроса. Для детальных денежных проверок нужны F0 и текущая дата из тест-дизайна.

## Критический путь

Цель — пройти покупку от карты до сохранённого результата и убедиться, что отказы не расходуют деньги. Выполняется после smoke на новых картах. Для CP-02–06 отключаем фоновую нагрузку; ожидаемые изменения статистики сравниваем с исходным снимком. Для каждой операции сохраняем PAN, STAN, RRN, сумму и время; асинхронные результаты ждём опросом до10 с.

- [ ] **CP-01.** Создать F0:201, ACTIVE, корректные PAN/Luhn/BIN и срок+3 года; GET200, баланс100000 и лимиты10000/50000. Требования: C-01, C-04, C-11; TC-C-01.
- [ ] **CP-02.** Отправить покупку A=2000 через Gateway, issuerId определяет Switch: APPROVED/00, mti0110, STAN совпадает. Требования: A-07; [ТЗ-03 §2](../../tz/03-switch.md); TC-A-02.
- [ ] **CP-03.** Проверить RRN12 цифр и authCode6 A-Z0-9; повторная независимая покупка имеет другой RRN, в том числе при отправке в одну секунду. Требование: A-12; TC-A-17.
- [ ] **CP-04.** B=98000, Ud=Um=2000 после покупки, один reserve; повтор того же прямого reserve с PAN/RRN/amount не списывает снова. Требования: A-08, C-12, C-13; TC-C-20.
- [ ] **CP-05.** Switch передал транзакцию через `smp.transactions`/`transaction.log` в `transaction-log`; Logger сохранил одну запись с тем же RRN, PAN, amount, APPROVED и исходным mti0100. Основание: [ТЗ-03 §3](../../tz/03-switch.md), [ТЗ-08 §2](../../tz/08-transaction-logger.md).
- [ ] **CP-06.** Транзакция поступила в `/ws/transactions`, отображена в recent и Dashboard; totalTransactions/approvedCount увеличились на1, totalAmount на2000. Основание: [ТЗ-08 §4–6](../../tz/08-transaction-logger.md), [ТЗ-09 §3](../../tz/09-web-dashboard.md).
- [ ] **CP-07.** На отдельных картах проверить отсутствующую→14, INACTIVE→CARD_INACTIVE, BLOCKED→CARD_BLOCKED, EXPIRED и истёкший срок→54. Требования: A-02, A-03; TC-A-03/04.
- [ ] **CP-08.** Изолированно превысить дневной остаток на1 коп.→61, месячный на1 коп.→61, баланс на1 коп.→51; равенство каждой границе при остальных валидных условиях→00. Требования: A-04/05/06; TC-A-05/06/07.
- [ ] **CP-09.** При совмещении превышения лимита и недостатка баланса действует приоритет ТЗ; для каждого отказа B/Ud/Um неизменны, Logger сохраняет DECLINED и причину при доступном брокере. Требования: A-08, A-09; TC-A-11/12/13; [ТЗ-08 §2](../../tz/08-transaction-logger.md).
- [ ] **CP-10.** Недоступная CMS даёт05/ISSUER_TIMEOUT без изменения usage; недоступный Bin Lookup при рабочей F0 сохраняет возможность APPROVED за счёт fallback. Требования: A-10, A-11; TC-A-14/15/16.
- [ ] **CP-11.** PATCH ACTIVE→BLOCKED меняет только статус; следующая авторизация возвращает CARD_BLOCKED. Требования: C-06, A-02; TC-C-11.
- [ ] **CP-12.** После DELETE карта скрыта в GET и списке, авторизация даёт14, reserve не меняет баланс; в БД DELETED. Требования: C-07, C-04, C-05, A-02; TC-C-12.
- [ ] **CP-13.** Create/PATCH/DELETE создают карточные outbox-события; при рабочем брокере PENDING→PROCESSED, Notification получает события по `card.*`. Требование: C-15; TC-C-23.
- [ ] **CP-14.** Если брокер не подтверждает публикацию одобренной покупки за2 с, Switch инициирует reversal, клиент получает DECLINED/96; баланс/usage восстановлены один раз. Основание: [ТЗ-03 §3–4](../../tz/03-switch.md); механизм reversal отмечен бонусным в ТЗ-04, но обязателен для этой гарантии Switch — конфликт фиксируем отдельно.
- [ ] **CP-15.** Повторная доставка транзакции с тем же id не создаёт вторую запись Logger. Основание: [ТЗ-08 §2](../../tz/08-transaction-logger.md).
- [ ] **CP-16.** Внешний запрос с отсутствующим обязательным полем, неверным PAN или amount0/-1 возвращает400/VALIDATION_ERROR до расхода средств. Основание: [ТЗ-02 §2](../../tz/02-gateway.md); Q-09 описывает отличие внутреннего API.
- [ ] **CP-17.** Merchant Simulator проводит одну покупку, Terminal Simulator выполняет заданное число запросов; результаты доступны в Logger и Dashboard. Основание: [ТЗ-06](../../tz/06-terminal-simulator.md), [ТЗ-07](../../tz/07-merchant-acquirer.md), [ТЗ-09](../../tz/09-web-dashboard.md).

Для любого непройденного пункта фиксируем фактический ответ и состояние. При противоречии источников используем `BLOCKED_REQUIREMENT` и номер Q; при подтверждённом нарушении однозначного требования — `FAIL` и дефект. Отсутствие сервисного прогона оставляет пункты незаполненными.
